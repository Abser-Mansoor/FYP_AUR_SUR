## 1. The project in six lines
- Goal: recognise faces in very small, low-quality surveillance imagery (QMUL-SurvFace, TinyFace, now video). Recognizers (inference only): ArcFace, AdaFace, MagFace, CurricularFace.
- Phases 0-2: baseline post-mortem, direct-feed baseline (TinyFace Rank-1 about 25% resize-only, 67-70% aligned), darkness/sharpness bins.
- Phase 3 closed SR as a negative result (supervisor brief, 2026-10-20). Phase 4 closed non-generative low-light/deblur by its pre-registered stop rule.
- The main deliverable is now the **video pipeline**: detection -> 5-point alignment -> AdaFace embedding + MagFace norm as quality -> ByteTrack/BoT-SORT -> per-track aggregation -> FAISS match. Restoration is an optional gated stage, off by default.
- Parent plan for the video work: `research/Sprint_Notes/Sprint_2_implementation_plan.md` (Phases 4-10).
- After every phase we write `REPORT_phaseN.md` and **stop for the supervisor's approval**.

## 4. Design of the recent phases
### Phase 5 (video foundations; plan `research/Sprint_Notes/Phase5_video_foundations_plan.md`, config `configs/video.yaml`)
- Data: ChokePoint (held, eye ground truth parsed, eye-to-box rule fitted from SCRFD detections, 1,000-frame seeded sample), WIDER FACE val (held). Requests for YTF, FANVID, COX, SCface and the IJB-S question are drafted in `docs/requests/`. Status per dataset in `DATASETS.md`.
- Environment `envs/video`; ByteTrack, BoT-SORT and RetinaFace vendored (`src/video/vendor/VENDOR.md`). SFE-DETR dropped (no code). CAFace and FaceMoE downloaded for later phases.
- Detector size study (5c): SCRFD and RetinaFace, each at `full640`, `full1280` and `tiled`, on WIDER val, the ChokePoint sample and the 22,898 Phase 3 eval crops. Run on a Colab T4 only. Selection rule fixed in `configs/video.yaml` before the run: highest WIDER recall on the 16-24 and 24-32 px bins at score 0.5, among configurations with median 720p runtime <= 100 ms; ties within 0.01 go to the faster one.

### Phase 4 (non-generative low-light and deblur; `configs/enhance.yaml`)
- Arms: bicubic pre-128 (control), gamma (adaptive), CLAHE, unsharp mask, Zero-DCE++, NAFNet (GoPro), plus a low-light gate and a deblur gate. Same tuning/eval subsets and selection rule as Phase 3.
- Pre-registered stop rule: restoration closes unless an arm gives a probes-only TinyFace Rank-1 gain with a 95% CI above zero for at least 2 of the 3 non-leaky recognizers. Result: 0 of 3 for every arm, so restoration is closed.
- Device: Raghib's laptop (Quadro RTX 3000) for every Phase 4 number, including its direct-feed baseline.

### Phase 3 design (historical)
- **Arms:** bicubic, Real-ESRGAN x4plus, InvSR, TADSR, OSDFace. Not attempted by instruction: DreamSR, FluxSR, ID-CDM, FideDiff.
- **Subsets** (fixed, seed 42, identity-stratified, disjoint): `tuning` = 2,800 crops, `eval` = 22,898 crops. Files: `outputs/sr/subset/{tuning,eval}_images.csv`, native-size inputs in `outputs/sr/subset/*_input/`. Config: `configs/sr.yaml`.
- **Flow per arm:** sweep settings on `tuning` -> pick one setting by the fixed rule -> run it on `eval` (seed 0) -> seed study (seeds 1, 2 on `tuning`).
- **Selection rule (fixed in advance):** highest mean over AdaFace, MagFace and CurricularFace of [TinyFace Rank-1, SurvFace verification AUC] on `tuning`. If a pre-size-256 setting wins, stop and ask the supervisor first (7-10 h on `eval`).
- **Restored crops are fed to recognizers** with INTER_AREA resize to 112 and flip-sum. Direct feed keeps the Phase 1 bilinear rule.
- **Leakage:** OSDFace's training uses an ArcFace identity loss. ArcFace is flagged as leaky in every OSDFace table; conclusions rest on the other three.
- **Known deviations** (all in `MODEL_INVENTORY.md`): torch 2.6.0+cu124 instead of the pinned 2.4.0 for InvSR and OSDFace (2.4.0 does not import on the PC); TADSR needs a runner-side `model.timesteps` workaround for outputs above about 768 px.

## 6. Running a Colab job (you only need this section)
The steps below are for the Phase 3 notebook. The Phase 5 detector study uses `phase5_detector_colab.ipynb` (generated by `colab/build_phase5_notebook.py`) in `FYP_SR_SHARED/phase5/`; it follows the same pattern (T4 assert, bundle check, SHA-256 check, cross-device check, resumable chunks, `DONE` file).

**One-time per account**
1. Open `FYP_SR_SHARED` in Drive, choose *Add shortcut to My Drive* (not needed for the folder owner).
2. Open `sr_phase3_colab.ipynb` from that folder in Colab.
3. Runtime > Change runtime type > **T4 GPU**. Keep the tab open and active.

**Every run**
1. Set `MACHINE = "T4-1"` (or T4-2, T4-3) in the first code cell.
2. Runtime > Run all. Setup takes 30-40 minutes (packages and weights), then the job starts.
3. The notebook verifies the bundle, builds the venv, downloads weights and checks their SHA-256, runs a cross-device check, then processes the job in chunks of 1,000 crops.
4. Progress prints `chunk k/N done`. Finished chunks are saved on Drive immediately.

**After a disconnect or crash:** just Run all again. Finished chunks are skipped; at most one chunk is redone.

**Done means:** the job folder on Drive contains a file named `DONE`. Tell the PC owner; they merge and score.

**Stop and report (do not continue) if:**
- the notebook asserts that the GPU is not a T4;
- "bundle ... incomplete": the PC has not finished syncing; wait and rerun;
- "checksum mismatch" or "weights do not match";
- the cross-device check fails (`xcheck.json` in the job folder).
Copy the red error text and the contents of `xcheck.json` to the team chat.
